# SEO
## 機能概要
* 本番ドメインは `https://every-music.com/`
* 各主要画面でtitle、meta description、canonical、OGP、Twitter Cardを出力する
* OGP画像は共通画像 `/images/ogp-default.svg` を使用する
* `/sitemap.xml` で公開ページを検索エンジンに通知する
* `/robots.txt` でクロール可能なページとログイン後の個人ページを整理する
* トップページでは、未ログインユーザー向けに作曲、演奏投稿、コラボ、フォロー、ランキングの特徴を説明する

## PWA
* `/manifest.webmanifest` でアプリ名、アイコン、theme-color、standalone表示を設定する
* `/service-worker.js` を登録する
* Service Workerはアイコンなど最小限の静的アセットだけをキャッシュする
* 認証ページ、録音ページ、音声再生、APIレスポンスは強くキャッシュしない
* アプリアイコンは `/images/pwa-icon.svg` を使用する
* iPhone向けにapple-mobile-web-app関連metaとapple-touch-iconを出力する

## 設定
* `PUBLIC_BASE_URL`
    * canonical、OGP URL、sitemap.xmlのURL生成に使用する
    * 未指定時は `https://every-music.com`
* `app.og-image-path`
    * OGP画像のパス
    * 初期値は `/images/ogp-default.svg`

## 公開URL
* `/`
* `/member/register`
* `/introduction`
* `/sitemap.xml`
* `/robots.txt`
* `/manifest.webmanifest`
* `/service-worker.js`
* 静的アセット

## Search Console運用
1. `https://every-music.com/` をGoogle Search Consoleに登録する
2. 可能ならドメインプロパティでDNS認証する
3. DNS認証が難しい場合はURLプレフィックスでHTMLまたはmeta認証する
4. `https://every-music.com/sitemap.xml` を送信する
5. インデックス状況とクロールエラーを確認する
6. クロールエラーがある場合は原因と対応方針を整理する

## 公開範囲の方針
* 未ログインで見せるのは `/`、`/member/register`、`/introduction`、`/sitemap.xml`、`/robots.txt`、PWA関連ファイル、静的アセットのみ
* 曲一覧、ランキング、曲詳細、マイページ、通知、タイムライン、API系は原則ログイン必須のまま
* SEO対応のためにログイン後ページの公開範囲を広げない

### 初期表示
1. 曲IDからsongsテーブルを取得
2. songs.creater_idからmember.member_nameを取得
3. songs.beat_idからbeat.nameを取得
4. 曲IDからsong_song_structureテーブルを取得
5. 曲IDからchord_progressionテーブルを取得
6. 曲IDからsong_playテーブルを取得
7. song_playを楽器種別ごとに分ける
8. song_play.player_idからmember_nameを取得
9. song_likeテーブルからコード進行へのいいね状態、いいね数を取得
10. song_commentテーブルからコード進行へのコメント数を取得
11. song_play_likeテーブルから各演奏へのいいね状態、いいね数を取得
12. song_play_commentテーブルから各演奏へのコメント数を取得

14. song_tag、tagsテーブルからタグを取得

16. ログイン中のmember_idとsongs.creater_idが同じ場合のみ募集内容とタグを編集可能とする
17. 楽器種別毎に演奏の中を分けて画面表示
    * 例えば、ドラム、ベース、リードギター、ボーカル毎に分けて表示
    * ラジオボタンもそれぞれの楽器毎に1つずつ選択できること

1. ログイン中のmember_idとsongs.creater_idが同じ場合のみ画面に表示する
2. 押下するとタグ編集モーダルを表示する
3. 現在のタグをカンマ区切りで表示する
### タグ保存ボタン
1. ボタン押下後、Serverにリクエストする
2. Server側でログイン中のmember_idとsongs.creater_idが同じであることを確認する
3. 作曲者でない場合はタグを更新しない
4. 入力されたタグをカンマ区切りで分割する
5. 空文字を除外し、重複を除外する
6. タグは5個以内、1タグ20文字以内とする
7. tagsテーブルに同名タグがある場合は既存タグを利用する
8. tagsテーブルに同名タグがない場合は新規作成する
9. song_tagテーブルの対象曲のタグを更新する
10. 更新後のタグを画面に反映する
### 募集内容を編集ボタン
1. ログイン中のmember_idとsongs.creater_idが同じ場合のみ画面に表示する
2. 押下すると募集内容編集モーダルを表示する

### 募集内容保存ボタン

# 追加DBテーブル
## いいね、コメント機能
* song_like
    * コード進行へのいいねを保持する
    * song_id、member_idの組み合わせを主キーとする
    * 1ユーザが1つの曲に対していいねできるのは1回まで
* song_comment
    * コード進行へのコメントを保持する
    * song_id、member_idの組み合わせをユニークとする
    * 1ユーザが1つの曲に対して投稿できるコメントは1件まで
* song_play_like
    * 演奏へのいいねを保持する
    * song_play_id、member_idの組み合わせを主キーとする
    * 1ユーザが1つの演奏に対していいねできるのは1回まで
* song_play_comment
    * 演奏へのコメントを保持する
    * song_play_id、member_idの組み合わせをユニークとする
    * 1ユーザが1つの演奏に対して投稿できるコメントは1件まで

## 演奏募集機能
* song_recruitment
    * 曲ごとの募集中パートを保持する
    * song_id、instrument_idの組み合わせをユニークとする
    * recruitment_noteに楽器ごとの募集コメントを保持する
    * statusが1の場合は募集中、0の場合は停止中とする
    * 募集内容を編集できるのは対象曲の作曲者のみとする

## アプリ内通知機能
* notifications
    * アプリ内通知を保持する
    * member_idに通知を受け取るメンバーIDを保持する
    * actor_member_idに通知のきっかけになったメンバーIDを保持する
    * notification_typeに通知種別を保持する
        * song_play_posted
        * song_liked
        * song_commented
        * song_play_liked
        * song_play_commented
        * member_followed
    * song_idに遷移先の曲IDを保持する
    * song_play_idに対象演奏IDを保持する
    * read_statusが0の場合は未読、1の場合は既読とする

## タグ機能
* tags
    * タグ名を保持する
    * tag_nameはユニークとする
    * タグ名は20文字以内とする
* song_tag
    * 曲とタグの紐づきを保持する
    * song_id、tag_idの組み合わせを主キーとする
    * 1曲に設定できるタグは最大5個までとする
    * タグを編集できるのは対象曲の作曲者のみとする

## フォロー、タイムライン機能
* member_follow
    * メンバー間のフォロー関係を保持する
    * follower_member_idにフォローするメンバーIDを保持する
    * followed_member_idにフォローされるメンバーIDを保持する
    * follower_member_id、followed_member_idの組み合わせを主キーとする
    * 自分自身はフォローできない
    * タイムラインはmember_follow、songs、song_playから検索して作成する

## ランキング、注目曲機能
* 新規テーブルは追加しない
* songs、song_like、song_comment、song_playからランキングを集計する
* 注目スコアは `いいね数 * 3 + コメント数 * 2 + 演奏参加数` とする

## DB反映SQL
* 新規構築時はsql/create_table.sqlに追加テーブル定義が含まれている
* 既存DBへ反映する場合はsql/add_interactions.sqlを実行する
* sql/add_interactions.sqlはCREATE TABLE IF NOT EXISTSで作成するため、既にテーブルが存在する場合は作成をスキップする
* 演奏募集機能を既存DBへ反映する場合はsql/add_recruitments.sqlを実行する
* sql/add_recruitments.sqlはCREATE TABLE IF NOT EXISTSで作成するため、既にテーブルが存在する場合は作成をスキップする
* アプリ内通知機能を既存DBへ反映する場合はsql/add_notifications.sqlを実行する
* sql/add_notifications.sqlはCREATE TABLE IF NOT EXISTSで作成するため、既にテーブルが存在する場合は作成をスキップする
* タグ機能を既存DBへ反映する場合はsql/add_tags.sqlを実行する
* sql/add_tags.sqlはCREATE TABLE IF NOT EXISTSで作成するため、既にテーブルが存在する場合は作成をスキップする
* フォロー、タイムライン機能を既存DBへ反映する場合はsql/add_follows.sqlを実行する
* sql/add_follows.sqlはCREATE TABLE IF NOT EXISTSで作成するため、既にテーブルが存在する場合は作成をスキップする
